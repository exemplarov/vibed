# 2026-10-06 — vibed: subtree dirs, ~ expansion, paginated API (0.17.0)

## What was built

Directory matching for listings grew two capabilities, an honest notice
system, and the API listing was fixed to page like the TUI:

- **Subtree dirs (`/*`)** — a `dirs` entry ending in `/*` matches the
  entry's own directory plus everything beneath it; plain entries stay
  exact-cwd matches (fully backward compatible). Implemented at every
  listing gate:
  - v2 SQLite + v1 SQLite: `directory = base OR substr(directory, 1, N)
    = 'base/'` — boundary-safe `substr`, not `LIKE` (paths contain `_`
    and `%`, which LIKE treats as wildcards).
  - v2 API: boundary prefix match client-side over the full paged list.
  - Transcripts: path-boundary prefix on real cwd (Codex); slug prefix
    for Claude/Cursor encoded dirs (documented lossy — slugs can't
    express boundaries).
- **`~` expansion** — `~` / `~/…` expand against the local home in block
  `dirs`, connector settings, and `basedir` — wherever the local
  filesystem is authoritative (DB + transcripts). API-only v2 listings
  (remote, no local DB) never expand: the remote home is unknowable;
  the entry stays literal and the dashboard shows an error. Gated by
  `driver.directoryCapabilities()` → `{ home, subtree }`.
- **Paginated API listing** — `GET /api/session` is cursor-paginated
  (default page: newest 50). The client now follows `cursor.next`
  (500/page, 30k cap), so API-only listings see the full session tree,
  exactly like the TUI. This is what makes `/*` work remote.
- **Dashboard notices** — a quiet strip between the toolbar and the
  list (small icon + small text, no filled background): errors first
  (`~` without direct access — expansion would point at the wrong
  machine), warnings (subtree globs on a `subtree: false` driver; empty
  directory config on OpenCode connectors — the "zero rows by design"
  trap). Recomputed every load.
- **New-session flow** — subtree globs are stripped (not working
  directories); unresolvable `~` entries error via Notice.

## Diagnosis trail that led here (useful for future remote debugging)

1. Remote connector "unreachable" → URL override was missing the port
   (`http://100.117.29.51` → port 80; server listens on 49374).
2. Zero sessions in API mode → client read only the first page, AND a
   freshly-restarted server briefly lists very few sessions (warm-up) —
   a bare probe right after restart returned 2 of 2684. Cursor paging
   returns all 2684.
3. `~/spaces` in a block silently matched nothing — no tilde expansion
   existed anywhere; now it expands (local access) or errors (API-only).
