# 2026-10-07 — vibed: chat UI round (0.19.0)

## What was built

Three composer/transcript UI additions closing the gap with the OpenCode
TUI's prompt experience. Spec: `spec/009-chat-environment-commands.md`.
All three are v2-only where they need server endpoints (capability-gated);
the jump button is purely client-side and works for every connector.

- **Jump to latest** — the transcript is a `column-reverse` scroller
  (`scrollTop` 0 = newest), so "scrolled away" is any `scrollTop < -60`. A
  floating button above the composer's right edge appears then; it counts
  NEW `oc-msg` records that arrived while away (badge: "3", caps at "9+"),
  clears on return. Sending snaps to the bottom instantly (the composer is
  viewport-fixed). Older-page loads bypass the counter
  (`renderOlderMessageEl` path); full reloads reset it in `resetMessages`.
- **Session environment popup** — header plug button (between Find and
  Notes) opens `SessionEnvironmentModal`: MCP servers for the session's
  directory with colored statuses (connected / disabled / failed + error /
  needs auth / needs client ID — the TUI sidebar's set) and inline
  Connect/Disconnect; slash commands and skills as compact lists. Refresh
  re-fetches all three; a total fetch failure says "Server unreachable"
  instead of "Nothing configured".
- **Slash commands** — typing a leading `/word` in the composer opens an
  autocomplete above it (substring filter, `↑`/`↓` wrap, `Tab` completes,
  `Enter` completes — or sends directly on an exact name match — `Esc`
  closes, rows are clickable via mousedown). Send routing follows the TUI's
  rule: `/name …` goes to `POST /api/session/:id/command` when the name is
  a loaded command (multi-line arguments preserved), otherwise it's a plain
  prompt. Works from drafts too (session created first, then routed).

## Server-compat findings (verified against local v2.0.23 + master source)

- `GET /api/command`, `GET /api/mcp` accept `location[directory]=…` and
  wrap results in `{location, data: […]}`; master's newer HttpApi returns a
  bare name→status record for MCP — `normalizeMcpList()` accepts all
  shapes (wrapped array / wrapped record / bare record).
- `POST /api/session/:id/command` on released v2 takes `{name, text}` and
  answers **204 no-body** (verified live with a scratch session, then
  interrupted + deleted). No synthetic user bubble is inserted then — the
  real one arrives via `session.inbox.enqueued` (already handled) or a
  scheduled reconcile as fallback. Master renamed the payload to
  `{command, arguments}` — `runCommand()` tries v1 first, retries once on
  4xx (validation failure = nothing executed, so the retry is safe), and
  caches the winning shape per connector.
- MCP per-server actions live at `/api/experimental/mcp/:name/{connect,
  disconnect}` on released v2, `/api/mcp/:name/…` on master — probed in
  order, prefix cached. A connect reply with `authorizationUrl` (OAuth)
  opens the authorization page instead of pretending success.
