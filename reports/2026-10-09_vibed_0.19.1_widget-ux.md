# 2026-10-09 — vibed: dashboard widget UX fixes (0.19.1)

## Problem

Embedded dashboards had a trap: a filter that matched nothing collapsed
the card list entirely, shrinking the embed until the toolbar (the only
way back out) was too cramped to use — the user was stuck filtered. On
top of that the toolbar was wordy ("Refresh", "New session") and the
filter popover could outgrow a short embed.

## What changed

- **Empty state (the trap fix)** — `renderEmptyState()` replaces the
  collapsed list when nothing renders: a one-card-tall dashed placeholder
  (`min-height: 4.6rem`) with contextual copy and, when a filter is the
  cause, a **Clear filter** button (`clearFilter()`). Widget mode
  (pinned `sessions:` only, no toolbar) gets its own "pinned sessions not
  found" message. `filterQueryActive()` checks every criterion
  (phrases/tags/states/dirs/models).
- **Filter popover** — now capped at `min(22rem, 50vh)` with internal
  scroll, so it never outgrows the visible pane, plus a header ("Filters"
  + ✕ close) so it is always dismissable even when tall.
- **Compact icon toolbar** — Refresh (`rotate-cw`), New session (`plus`),
  and the opt-in Settings (`settings`) buttons are now icons with
  tooltips, sharing one `opencode-sessions-tool-button` class with the
  filter/copy buttons (old `opencode-sessions-filter-menu-button` class
  removed).
- **Spacing** — toolbar gap 0.6 → 0.4rem; `filter-tools` gained a 0.25rem
  gap so the filter and copy icon buttons no longer read as one merged
  control.
- **Smaller filter text** — filter input → `--font-smaller`, filter chips
  → `--font-smallest`.
- **Obsidian block-edit button** — toolbar reserves the top-right corner
  (`padding-right: 1.9rem`) so the hover edit button in live preview never
  overlaps the last toolbar control.
